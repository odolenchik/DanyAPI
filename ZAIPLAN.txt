# Провайдер z.ai (chat.z.ai) — browser-proxy

## Цель и выбранный подход
Третий провайдер — z.ai / GLM (`https://chat.z.ai`). Наружу отдаём те же
OpenAI-совместимые ответы через `POST /v1/chat/completions`.

Изначальный план (см. git history) предполагал полный паритет с Qwen:
reverse-engineered веб-API, `ZaiClient`, `QwenSessionRegistry`-подобная
сессия, стриминговый реконструктор. На практике chat.z.ai требует one-shot
Aliyun CAPTCHA на каждый completion-запрос, поэтому основной путь ушёл в
**headed-Chrome browser-proxy через Playwright**. Отдельный read-only httpx
клиент (`client.py` / `ZaiClient`) для models/config оказался не нужен —
модели берутся из жёстко заданного списка `ZAI_DEFAULT_MODELS`. Файл удалён.

## Текущее состояние (закоммичено)
- Конфиг: `danyapi/config.py` читает `ZAI_TOKENS` / `ZAI_TOKEN`,
  `ZAI_EMAIL`, `ZAI_PASSWORD`. `.env.example` обновлён.
- Пакет `danyapi/zai/`:
  - `browser.py` — `ZaiBrowser`: Playwright-driven headed Chrome; авторизация
    по токену, ручное решение капчи в открытом окне, completion через веб-чат,
    `_CompletionAccumulator` (content / reasoning / usage / error).
  - `api.py` — `collect_non_stream(browser, prompt, model)`: сборка
    OpenAI-ответа (message + optional reasoning_content + usage). Таймаут → 504.
  - `__init__.py`.
- Интеграция в FastAPI (`danyapi/api/openai.py`):
  - lifespan: при наличии `settings.zai_tokens` создаётся один `ZaiBrowser`,
    `app.state.zai_browser`, `app.state.zai_models = ZAI_DEFAULT_MODELS`;
    закрытие через `aclose()` в finally.
  - `_resolve_provider`: префиксы `glm*` / `zai*` → `"zai"`.
  - `_chat_completions_zai(req)`: non-stream; при `req.stream` → **501**
    ("streaming is not supported yet").
  - `list_models` включает z.ai-модели.
- Инварианты: `scripts/arch-check.py` — пакет `"zai"` в PACKAGES.
- Тесты: `tests/test_zai.py`.

## Ограничения (по сравнению с Qwen/DeepSeek)
- **Стриминг не поддержан** — `_chat_completions_zai` возвращает 501 при
  `stream=true`. Это главный функциональный разрыв.
- Один браузер на процесс; completion идёт через живой Chrome, а не прямой
  httpx-вызов (медленнее, требует дисплея/ headed-режима).
- z.ai не участвует в учёте токенов (`usage.py`) — как и Qwen, осознанно.

## Остались работы
### Стриминг (основная)
Реализовать SSE-стриминг для z.ai через Playwright: читать ответ чата по мере
поступления, эмитить OpenAI `chat.completion.chunk` события (delta content /
reasoning), убрав 501 в `_chat_completions_zai`. Ориентир — стрим Qwen
(`danyapi/qwen/api.py::stream_openai`) и DeepSeek (`danyapi/api/streaming.py`).

### Мелкие
- При необходимости: поддержка tool calls для z.ai (сейчас prompt собирается,
  но парсинг/формат вызовов не подтверждён на живом токене).
- E2E на реальном токене: `/v1/models` и `/v1/chat/completions` (stream + non-stream).

## Критерии готовности (DoD) — для задачи «стриминг»
- `ruff check` и `ruff format --check` зелёные.
- `python -m pytest -q` зелёные; покрытие не падает ниже текущего уровня.
- `make arch-check` зелёный.
- E2E на реальном токене: стриминговый ответ отдаётся чанками, 501 убран.
- OpenAI-контракт `POST /v1/chat/completions` не изменён.
